# T2 instruments and MIDI FX

Phase 6, workstream E ([docs/07-phase-6.md](../07-phase-6.md)). Six instruments against `IInstrument` and eight MIDI
effects against `IMidiEffect`, all in `Anode.Dsp`, registered in `BuiltinInstruments` and `BuiltinMidiEffects`, with
macro hints for Smart Controls on every built-in instrument (T1 included) and every MIDI effect.

## Instruments

| Id | Name | Voices | Design |
|---|---|---:|---|
| `anode.drum-synth` | Drum Synth | 8 | One drum sound an instance: kick, snare, clap, hat, tom, cymbal or percussion (the `model` parameter), analogue-style (808/909 circuits: swept sines, metallic squares, band-passed noise). Every note plays the same hit, so a Drum Machine Designer pad's note never changes the sound. |
| `anode.fm` | FM Synth | 16 | 4 sine operators (ratio 0.5–16 and fine tune, own ADSR, level, velocity sensitivity), 8 algorithms after the 4-operator Yamaha synths, feedback on operator 4, mod-wheel vibrato. |
| `anode.organ` | Drawbar Organ | 32 | Tonewheel additive (9 drawbars with foldback), single-triggered percussion (2nd/3rd, fast/slow, soft/normal; cuts the 1' drawbar), key click, scanner vibrato/chorus V1–C3, built-in rotary (drive, 800 Hz crossover, horn and drum rotors with inertia, Doppler and AM, two mics 90° apart; the mod wheel switches to fast). |
| `anode.electric-piano` | Electric Piano | 32 | Modelled tines (fundamental, tonebar octave, inharmonic bell partial at 7.13×, hammer thump, magnetic pickup `p + b·p²`) and reeds (reed harmonics through the electrostatic pickup `p / (1 − b·p)`); pitch-dependent decay, damper, pedal; pan tremolo (tines) or amplitude tremolo (reeds). |
| `anode.wavetable` | Wavetable Synth | 16 | 2 wavetable oscillators (5 banks × 8 frames generated in code, band-limited at 10 levels, position morphs between frames), sub (sine/square), noise, multimode filter, 3 ADSRs (amp, filter, mod), 2 per-voice LFOs (Hz or synced to the transport), 6-slot modulation matrix. |
| `anode.quick-sampler` | Quick Sampler | 16 | One WAV: one-shot, classic (ADSR, loop), slice (transients or 4–32 equal parts, one a key from Slice Start Note) and recorder (records the input fed to it, then plays the take); Key Follow off plays at the root. |

All follow the T1 structure: a public sealed class wrapping a private `PolyInstrument<TVoice>` engine (sample-accurate
events, the 16-sample control grid, voice stealing with a 5 ms fade, sustain pedal, mod wheel, bend, CC 120/121/123),
parameters through `ParameterBank`, state through `InstrumentState` (`ANIS`, by parameter id). Their voices update on their
own control grid from their start, and the effects that run after the voices (organ scanner and rotary, piano tremolo)
rest while the instrument is quiet and start from the same point, so a note sounds the same wherever it falls and
whatever the buffer size (the contract tests check both, to the bit). The Quick Sampler loads `.wav` (`FileTypes`);
the others load nothing.

Shared helpers: `ParameterList` (builds a parameter list in index order, returning each index), `ParameterSmoother`
(control-rate smoothing as `anode.synth`'s), `SineTable` and `Pitch` (`Instruments/`), `IPolyphonic` (voices, for tests
and diagnostics), `NoteDivisions` and `Scales` (`MidiEffects/MidiEffect.cs`).

### State beyond the parameters

- **Quick Sampler**: the file's absolute path, as the T1 sampler. A recorded take (no file) is appended after the
  parameters: `QSTK`, the sample rate and frame count (int32), then the left and right channels as float32.
- **Chord Trigger**: the learned chords after the parameters: `CHRD`, the single chord's intervals (count, then sbytes),
  then the multi-mode chords (count, then key, note count and notes, a byte each).

`InstrumentState.TryRead` got an overload that says where the parameters end, for these.

## MIDI effects

| Id | Name | Design |
|---|---|---|
| `anode.arpeggiator` | Arpeggiator | Held notes on a grid of 15 note lengths (1/1 … 1/32, dotted and triplet): up, down, up-down (ends not repeated), random (seeded), as played; 1–4 octaves; gate 5–100 %; swing (every second step later by swing × half a step); latch; fixed or played velocity. While playing, step `k` is quarter note `k · rate` of the project (through ramps and cycle jumps); stopped, the grid runs from the chord's first note. A step sounds on the first sample at or after its position. |
| `anode.chord-trigger` | Chord Trigger | Single mode: one of 11 chord types or the learned chord on every key; multi mode: each key's learned chord. Learn collects the keys held together. Shared notes are reference-counted. |
| `anode.modifier` | Modifier | One controller remapped to a controller, channel aftertouch or pitch bend, scaled and offset, optionally passing the original. |
| `anode.modulator` | Modulator | An LFO (5 shapes, Hz or synced) plus an attack/release envelope gated by held notes, sent as a controller (or aftertouch, bend) every 32 samples when the value changes. |
| `anode.note-repeater` | Note Repeater | 1–32 repeats of each note at a note length, with a velocity ramp, a transpose per repeat and a gate; timed on the effect's own clock (the contexts' tempi), so it rides through stops and jumps. |
| `anode.randomizer` | Randomizer | Note chance, velocity ±range, pitch ±range with its own chance; deterministic from a Seed parameter (reseeded on reset or a seed change). |
| `anode.transposer` | Transposer | Semitones, then (with a scale: 12 scales on any key) snapped to the scale (a tie goes down) and moved by scale degrees. |
| `anode.velocity-processor` | Velocity Processor | Scale, offset, compression or expansion above a threshold, min/max limits. |

They share `MidiEffect` (internal): descriptor, `ParameterBank`, `ANIS` state, note helpers. Every one keeps a note-off
paired with what its note-on became (per channel and key), so no note hangs; other events pass through (the
Arpeggiator consumes the held notes' own note events). None allocates in `Process` (checked).

## For the editor (workstream C)

Parameter ids are stable (projects store values by id). The appendix lists every parameter. Patterns for the custom
panels:
- **Drawbars**: `drawbar1` … `drawbar9` (16', 5⅓', 8', 4', 2⅔', 2', 1⅗', 1⅓', 1'; `OrganParameters.Footages`), each
  0 … 8 in 8 steps, default 888000000. Next to them: `percussion`, `percussionHarmonic`, `percussionDecay`,
  `percussionVolume`, `keyClick`, `vibratoChorus` (Off, V1–V3, C1–C3), `rotary`, `rotarySpeed` (Stop, Slow, Fast),
  `rotaryDrive`, `rotaryBalance`.
- **FM algorithm picker**: `algorithm`, a choice of 8 whose value names draw the routing (`1: 4→3→2→1`,
  `2: (3+4)→2→1`, `3: (3→2)+4→1`, `4: (4→3)+2→1`, `5: 2→1, 4→3`, `6: 4→1, 4→2, 4→3`, `7: 4→3, 2, 1`,
  `8: 1, 2, 3, 4`); operator 4 has the `feedback`. Operators are `op{n}Ratio`, `op{n}Fine`, `op{n}Level`,
  `op{n}Attack`, `op{n}Decay`, `op{n}Sustain`, `op{n}Release`, `op{n}Velocity` for `n` = 1 … 4. The routing as data:
  `FmAlgorithms.Routing(algorithm)` (modulators per operator and the carriers).
- **Wavetable synth**: `osc{1,2}Table` (Basic, Harmonic, Formant, Sync, FM), `osc{n}Position`, `osc{n}Octave`,
  `osc{n}Semitone`, `osc{n}Fine`, `osc{n}Level`; `env{1,2,3}{Attack,Decay,Sustain,Release}` (1 amp, 2 filter, 3 mod);
  `lfo{1,2}{Shape,Rate,Sync}`; the matrix `mod{1…6}{Source,Destination,Amount}` (sources and destinations are choices
  with names).
- **Drum Synth** (DMD pad editor): `model` and `tune`, `decay`, `tone`, `snap`, `sweep`, `drive`,
  `velocitySensitivity`, `pan`, `volume`.
- **Quick Sampler** (DMD pad editor): `mode`, `rootNote`, `keyFollow`, `tune`, `fine`, `start`, `end`, `loop`,
  `loopStart`, `loopEnd`, the ADSR, `sliceMode`, `sliceStartNote`, `recordArm`, `recordThreshold`. A waveform view
  needs the file (the strip's `file`); slice points are `QuickSampler.Slices` (engine side only today).
- **Arpeggiator button**: `anode.arpeggiator` (`BuiltinMidiEffects.ArpeggiatorId`); its first macros are `rate`,
  `mode`, `octaves`, `gate`.

Macro hints: every instrument and MIDI effect has at least four, in the order Smart Controls should take them (the
appendix's Macro column; T1: the synth's cutoff, resonance, filter envelope, amp attack and release, osc mix, LFO
rate, glide, unison detune, filter decay, amp decay, volume; the sampler's tune, attack, release, velocity sensitivity,
volume; the organ's drawbars first).

## For the engine (workstream A)

- **MIDI FX output volume** per block, for an input of `n` events (the buffer holds 1,024):
  - Arpeggiator: at most two events a step (a note-off and a note-on) plus the pass-through; a step is at least a
    1/32 triplet (1,000 samples at 120 bpm), so a 1,024-frame block carries a handful.
  - Chord Trigger: up to 12 note-ons (or offs) per input note.
  - Note Repeater: the input, plus two events per repeat as they fall due (up to 64 per note, spread over the repeats;
    512 pending at most).
  - Modulator: the input plus one event per 32 samples (32 in a 1,024-frame block).
  - Modifier: up to 2 per input event (with Thru); Transposer, Randomizer: up to 2 per note-on (ending a still-sounding
    mapping first); Velocity Processor: 1:1.
  - Events added past `MidiEventBuffer.Capacity` are dropped (`Add` returns false), never thrown.
- **Transport**: the MIDI effects read the context's `Frames`, `Quarter`, `Bpm`/`QuartersPerSample` and `Playing`
  (Arpeggiator, Note Repeater, Modulator); a cycle jump is a discontinuity in `Quarter` that the Arpeggiator re-anchors
  on. Only **`anode.wavetable`** among the instruments needs `SetTransport` (its synced LFOs: phase = position over
  the note length while playing, the context's tempo otherwise); the others take the default (ignore it). It is
  called before every `Process` with that call's frames (32-frame pieces for automated plugins are fine: the synth
  counts frames from the last context); `WavetableSynth` lists `IInstrument` itself and declares the method, so the
  call through the interface reaches it (the allocation test calls it through `IInstrument`). It does not allocate
  (tested for every T2 instrument).
- **Drum Machine Designer**: pads get the DMD note unchanged. The Drum Synth ignores it; a Quick Sampler pad needs
  `keyFollow` 0 (its pad mode: every note plays at the root), which the server sets when it puts one on a pad.
- **Quick Sampler recorder feed**: `QuickSampler` implements `IInstrumentInput` (new, public, in
  `Anode.Dsp.Instruments.Quick`): `Feed(ReadOnlySpan<float> left, ReadOnlySpan<float> right)`, on the audio thread,
  once per block before `Process`, with the track's input for that block (the same frames). The engine should do this
  for any instrument that `is IInstrumentInput` on a track whose input is set (the input bus, after its gain; while the
  track is record-enabled or monitoring, as the server decides). Room for a take (30 s) is made on the control thread:
  `Prepare` does it when the mode is Recorder, and `PrepareRecorder()` does it on demand (call it when the server
  switches a Quick Sampler to recorder mode, or re-prepare the instance). Recording starts at the first input sample at
  or above `recordThreshold` while `recordArm` is on, and stops when `recordArm` goes off or the 30 s are full; the take
  becomes the sample and goes into the state (`SaveState`), so the server should save the strip's state after a take.

## For the server and content (workstream B)

- **A Drum Synth pad**: `addDrumPad` / `setDrumPad` with instrument `anode.drum-synth`, then parameters: `model`
  (0 Kick, 1 Snare, 2 Clap, 3 Hat, 4 Tom, 5 Cymbal, 6 Percussion) and the sound (`tune` ±24 st, `decay`, `tone`,
  `snap`, `sweep`, `drive` in %, `pan`, `volume` dB). It ignores the note, so the pad's note routing needs nothing
  else. A closed and an open hat are two pads (`decay` about 15 and 70). Suggested kit: kick (decay 45, drive 30),
  snare (snap 70), clap (volume −12), closed hat (decay 15), open hat (decay 70), tom (tune +3), cymbal, cowbell
  (percussion, tone 90).
- **A Quick Sampler pad**: instrument `anode.quick-sampler`, `LoadFile(path)` of a `.wav` (any rate, mono or stereo;
  a `smpl` unity note sets `rootNote`), `mode` 0 (one shot) and `keyFollow` 0, so whatever note the pad passes plays the
  sample as recorded. The state holds the file's absolute path: a kit in a pack should store the sample relative to the
  kit and the server load it (or rewrite the path) on install, as the T1 sampler's SFZ files are handled.
- **Content builder**: render offline as `DemoTests`/`T2DemoTests` do (`Prepare(48 kHz, block)`, set parameters,
  `Process` blocks of events). `T2DemoTests.Render_t2_demos` is a worked example of a Drum Synth kit, FM, organ,
  pianos, a wavetable pad, an arpeggiated synth (Arpeggiator → `anode.synth`) and a Quick Sampler slice pattern.
- **Pattern rows of kind `pad`**: nothing instrument-specific; the note goes to the pad.

## Contract notes

- No contract changed. Additions: `IInstrumentInput` (public, for the recorder feed); `IPolyphonic` (internal);
  `InstrumentState.TryRead(…, out int end)` (internal). `IInstrument.SetTransport` is implemented by
  `WavetableSynth` only.
- The MIDI effect classes are internal (their descriptors and `BuiltinMidiEffects.Create` are the public surface, as
  the contract has it); `ChordTrigger.SetChord`/`GetChord` are reachable in-assembly and by tests. The server sets
  learned chords through the state blob.
- `Anode.Engine.Tests.HostMidiTests` listed the catalogue's built-in instruments literally; it now takes them from
  `BuiltinInstruments.All`.
- The Quick Sampler's `.wav` only (the `WavReader`), as the T1 sampler. AIFF/FLAC would need a reader.
