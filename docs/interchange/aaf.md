# AAF

How Anode moves an arrangement of audio to and from Pro Tools, Media Composer, Logic and other editors through the
Advanced Authoring Format: the subset written and read, the Avid conventions followed, and what is lost. The plan is
[Phase 9](../10-phase-9.md), workstream E.

The code is `engine/src/Anode.Interchange/Aaf`, pure file formats with no project I/O of its own:

- `Cfb.CfbWriter` and `Cfb.CfbReader`: the Microsoft Compound File Binary container ([MS-CFB]), Anode's own
  implementation ([ADR-0008](../adr/0008-third-party-licensing.md)).
- `AafStorage.cs`: AAF's structured storage on top of it: objects, properties, strong and weak references, sets,
  vectors and their index streams, stream properties.
- `AafMetaModel.cs` and `AafMetaModel.g.cs`: the standard class and type definitions, which every file carries as its
  MetaDictionary. The `.g.cs` is generated by `scripts/aaf-model.py` from pyaaf2's model tables.
- `AafWriter.Write(state, projectFolder, request, path)`: the export. It returns the files written, the AAF first.
- `AafReader.Read(path, mediaFolder)` gives an `AafComposition`; `AafReader.ToContent(composition, state, fileIds)`
  turns it into the `ImportedContent` of an `importTracks` command. The server's jobs (workstream B) copy the media
  into the project between the two.

## The container

- **Version 4** (4096-byte sectors) is written, as the AAF SDK and pyaaf2 write it. Version 3 (512-byte sectors) is
  available to tests.
- The writer works in one sequential pass. The header comes first, then each large stream straight from its source,
  then the mini stream, the mini FAT, the directory, the FAT and the DIFAT. Every size is known before the first byte,
  so embedded audio of hundreds of megabytes is copied from the WAV file in 64 KiB blocks and never held in memory.
- Siblings are linked as a size-balanced binary tree. Its deepest level is red when the tree is not perfect, which
  makes it a valid red-black tree.
- The reader loads the FAT (through the DIFAT), the directory and the mini FAT. Streams are read in place through
  their sector chains.
- A file that breaks the format is refused with `FormatException`: no signature, a bad header, a chain that loops or
  leaves the file, a directory tree with a cycle, a truncated file.
- [MS-CFB] pairs version 3 with 512-byte sectors and version 4 with 4096-byte sectors. pyaaf2 labels 512-byte files
  version 4, so the reader accepts either sector size under either version.

## The object model written

Each AAF object is a storage whose class id is its class. It holds a `properties` stream: byte order `0x4C`, version
32, then (pid, stored form, size) entries and their data. Child objects are storages named after the property, mangled
to 31 characters as the SDK mangles them. Strong reference vectors and sets have an `index` stream, and sets are keyed
by their elements' unique ids. Weak references store the target's key and an index into the root's
`referenced properties` table of pid paths.

| Object | What Anode writes |
|---|---|
| Root | `MetaDictionary` and `Header`, and the `referenced properties` table |
| MetaDictionary | Every standard class definition (with its property definitions) and every type definition of AAF v1.1, as pyaaf2 tabulates them. Avid's extensions are left out. Properties without a fixed pid get dynamic ones from `0xFFFF` down |
| Header | Byte order `II`, last modified, version 1.1, object model version 1, operational pattern Edit Protocol, one `Identification` (Anode, its version, a fixed product id) |
| Dictionary | Data definitions Sound and DescriptiveMetadata; operation definitions Mono Audio Gain (parameter Amplitude) and Mono Audio Dissolve; parameter definition Amplitude (Rational); the container definition AAF (embedded media) or RIFFWAVE (linked media) |
| CompositionMob | The project's name, usage code `Usage_TopLevel`, a `TimelineMobSlot` per audio track and an `EventMobSlot` for the markers |
| TimelineMobSlot | Slot id and physical track number 1, 2, …; the track's name; edit rate = the project's sample rate; origin 0; a `Sequence` of sound |
| Sequence | `Filler`s for gaps, a clip per region, a `Transition` per crossfade |
| SourceClip | Refers to the file's MasterMob, slot 1, at `StartTime` = the region's file offset; its length is the region's length; `FadeInLength`/`FadeOutLength` (type linear amplitude) for fades that are not crossfades |
| Clip gain | Avid's convention: the clip inside an `OperationGroup` of Mono Audio Gain, with a `ConstantValue` Amplitude as a Rational linear ratio (the largest power-of-two denominator that fits: 2³⁰ for gains up to 0 dB). The SDK keeps an operation group's parameters as a set keyed by definition, as pyaaf2 does |
| Transition | The overlap's length, cut point at half, an `OperationGroup` of Mono Audio Dissolve |
| Markers | `DescriptiveMarker`s (data definition DescriptiveMetadata) in a `Sequence` on the event slot: `Position` and `Length` in samples, the marker's name as `Comment`, its text as a `UserComments` tagged value named `Comment` |
| MasterMob | One per audio file, named after it: one slot of the file's length referring to the file SourceMob |
| SourceMob | A `PCMDescriptor`: sample rate, length in frames, channels, quantisation bits, block align, average bytes per second, container format. With linked media, a `NetworkLocator` with the WAV's absolute `file://` URL |
| EssenceData | For embedded media: keyed by the file SourceMob's MobID, its `Data` stream the interleaved little-endian PCM samples |

**MobIDs** are SMPTE UMIDs (label `060a2b34 01010105 01010f20`, length `0x13`). Their material number is a hash of the
project id and the file id, so exporting the same project twice gives the same MobIDs.

**Channels:** one timeline slot per track, and one PCM descriptor per file with the file's channel count (mono or
interleaved stereo). Media Composer splits stereo into mono slots and mono files. pyaaf2 and the AAF object
specification accept multichannel PCM, and Anode's reader takes either.

**Sample formats:** 16-, 24- and 32-bit integer files are embedded or copied byte for byte. Float files become 24-bit
PCM, as Avid does not read float PCM in AAF.

**Linked media** are written into `<file name> Media/` beside the AAF. An integer PCM file is copied as is; a float file
is converted to 24-bit.

## The object model read

The reader takes what Anode writes and what Pro Tools, Media Composer and pyaaf2 write:

- **The composition:** the CompositionMob with usage code `Usage_TopLevel`. Without one, a composition no other mob
  refers to.
- **Tracks:** every `TimelineMobSlot` whose segment is Sound (or legacy Sound) becomes a track, named after the slot
  (`Audio n` when it has no name). A mono slot from Media Composer is a mono track; the reader does not pair L and R
  slots.
- **Timing:**
  - Positions come from the sequence: fillers and clips add their lengths, transitions overlap.
  - The composition's sample rate is the first audio slot's edit rate when it is a whole number of Hz from 8 kHz up.
    Otherwise it is the media's sample rate. Slots at other edit rates are converted.
- **Clips:**
  - A `SourceClip` is followed through MasterMobs and SourceMobs to a file SourceMob, adding up the start times on the
    way.
  - `OperationGroup`s are passed through to their first input. Mono and stereo audio gain multiply in their constant
    Amplitude, in dB.
  - A `Transition` becomes an overlap: a fade out on the clip before and a fade in on the clip after, both its length.
    Other fades come from `FadeInLength`/`FadeOutLength`.
- **Embedded media:**
  - An `EssenceData` with raw PCM (PCM or Sound descriptor; 16, 24 or 32 bits) is written to a WAV file in the job's
    media folder, named after the master mob.
  - An essence stream that is already a RIFF file is copied as is.
  - AIFC essence is refused.
- **Linked media:** a `NetworkLocator`'s file URL is used when the file exists. Otherwise the reader looks for its file
  name in `<file name> Media/` beside the AAF, then beside the AAF itself. When neither has it,
  `FileNotFoundException`.
- **Markers:** `DescriptiveMarker`s and `CommentMarker`s on event slots, with `Comment` as the name and a `UserComments`
  `Comment` as the text.

`ToContent` makes an audio track per AAF track and a region per clip:

- A position in samples becomes ticks through the project's tempo map. Where no tick lands exactly on the sample (at
  120 BPM and 48 kHz a tick is 25 samples), the region starts at the last tick before it. Its file offset, length and
  fade in grow by the difference, so every file frame plays at the very sample the AAF gives it. When the clip has too
  little audio before it, the region starts at the next tick and drops those samples.
- A composition at another sample rate is scaled to the project's. The import job resamples media at another rate to
  the project's with the bounce's resampler (as the Audio File Editor's rate conversion does) before copying them in, and
  a region never reaches past its file's end.
- Markers come back as markers. AAF carries no tempo, so the project's tempo is kept.

## What is lost

- **Region names:** a clip is named after its media (the master mob), as Avid names clips.
- **Fade curves:** fades are lengths; their shape (Anode's curve) is not written, and comes back linear.
- **Crossfades that are not symmetric:** a crossfade is the overlap. A region whose fade into the next is longer or
  shorter than their overlap comes back with the overlap's length.
- **Overlaps that are not crossfades:** an overlap longer than a transition can be (longer than the later region, or
  than what the earlier one has left after its own incoming crossfade) shortens the earlier region.
- **Warped regions** (flex, follow tempo, transpose, fine tune, pitch notes) are written by their file offset and
  length, unwarped.
- **Muted regions** are left out, as are MIDI, instrument and other tracks that are not audio. SMF covers MIDI.
- **Out of scope:** volume and pan automation, plug-ins, sends, track colours, video and Avid's private attributes
  (`_ATN_…`). Clip gain automation (a varying Amplitude) reads as no gain.
- **Marker colours** are not written.

## Verification

- `python3 scripts/setup-pyaaf2.py` makes a virtual environment with pyaaf2 1.7.1 (MIT) at `engine/artifacts/pyaaf2`.
- The opt-in tests (`engine/tests/Anode.Interchange.Tests/Aaf/PyAafTests.cs`) run when that environment exists, or when
  `ANODE_PYAAF2` names a python with pyaaf2. They are skipped otherwise.
  - They export the test arrangement, embedded and linked, and read it with `scripts/aaf-check.py`.
  - They check every clip's position, source offset and length to the sample, the fades, the transition, the clip
    gain, the embedded essence's SHA-256 against the source samples, the locators' URLs and the markers.
- `scripts/make-aaf-fixtures.py` writes the import fixtures with pyaaf2: `Aaf/Fixtures/pyaaf2-embedded.aaf` and
  `pyaaf2-linked.aaf` with `linked-tone.wav`. Its header lists their content, which `AafFixtureTests.cs` checks in the
  normal test run.
- Beyond the tests, pyaaf2 also opens Anode's exports read-write and saves them, and olefile reads Anode's compound
  files in its strict mode.
- `scripts/aaf-model.py` regenerates `AafMetaModel.g.cs`.
